# ЛР3 · Контейнеризація та локальне розгортання сервісу

Повний текст інструкції — у файлі `ЛР3_Методичні_вказівки.docx`. Цей
README — лише технічна навігація.

Python-код (`app/`, `tests/`, `scripts/`) — це ГОТОВИЙ, повністю
робочий еталон ЛР1+ЛР2 (без TODO). ЛР3 не редагує жодного рядка
Python-коду — вся робота цієї лабораторної в Docker-артефактах навколо
нього.

Два рівні:

- **Базовий (обов'язковий)** — кроки 1–8: Dockerfile (multi-stage),
  .dockerignore, healthcheck на /health, docker compose з api+nginx,
  том для моделі.
- **Поглиблений (додатково)** — кроки 9–12: CPU-only збірка torch
  (без CUDA-бібліотек), непривілейований користувач, тривимірне
  порівняння розміру образів.

## Структура

## Передумови

Ця робота продовжує ЛР2 — перед початком мають існувати:

```bash
ls models/onnx-fp32    # з ЛР2, крок 2
ls models/onnx-int8    # з ЛР2, крок 10 (поглиблений рівень)
```

Якщо їх немає — повернутися до ЛР2 і виконати export/quantize.

## Порядок виконання

Повністю розписано в методичці, розділ 5. Коротко:

1. Підготовка — перевірити наявність Docker і моделей з ЛР2.
2. Перші команди Docker (образ, контейнер, docker run/ps/images).
3. Наївний одноетапний Dockerfile — відчути проблему (розмір, повільний ребілд).
4. Виправлення на multi-stage (venv, COPY --from=builder).
5. HEALTHCHECK на /health.
6. .dockerignore.
7. compose.yaml: сервіс api, том моделі, змінні середовища.
8. nginx: reverse proxy, сервіс nginx у compose.yaml.
9. `bash verify.sh` — має пройти без FAIL, звіт базового рівня.

Поглиблений рівень:

10. CPU-only torch (без CUDA).
11. Непривілейований користувач.
12. Тривимірне порівняння розмірів образів.
13. `bash verify.sh advanced`, звіт поглибленого рівня.

## Важливо

Docker-команди в цьому README і в методичці розраховані на **вашу
власну машину** — перевірити їх виконання на 100% ще до здачі роботи
означає реально запустити `docker compose up` і побачити результат.
